# Clients speak one versioned contract: commands, queries, two feeds

Every Factory client — the v1 CLI, and later the Project Console, Node View, Project Assistant, and any remote worker — speaks one **Client Contract**, `factory-api/v1`: HTTP/1.1 and JSON on one `POST /v1/rpc` endpoint over a Unix domain socket, where each call is a **command**, a **query**, or a **subscription**. Commands are the only writes, they carry a client-generated idempotency key, and their receipts are rows in the same SQLite database committed in the same transaction as the transition they witness. Queries read projections and return the transition-log sequence they read at (`asOf`), so a client can join a read to a feed with no gap or duplicate. Subscriptions come in two feeds with different guarantees: the **durable feed** streams the transition log from a sequence cursor, gapless and replayable after a snapshot, and disconnects a subscriber that falls behind rather than skipping; the **live telemetry feed** streams the activity event log, is explicitly lossy, and reports loss as `gap` (the source could not observe) or `drop` (this subscriber fell behind). The contract is the source of truth in JSON Schema 2020-12 plus a hand-written operation index; the boundary is already JSON (the compiled IR, the activity envelope, this API), which is why a second encoding buys nothing; the transport is one versioned major with a capability descriptor, and changes inside it are additive only. Transport, auth, and versioning are sized to one Owner on one machine: a bearer token file at `0600`, a Linux `SO_PEERCRED` check, and declared operation scopes whose v1 grants are broad. Operation targets are refs, artifact content travels in the request, and no operation takes a host filesystem path. The contract is specified in [`docs/spec/API.md`](../spec/API.md), summarized by the spec's §2.7, and proved by a fake second client that is not the CLI.

## Considered Options

- **REST-shaped resources** — rejected: no caches, no intermediaries, no third-party clients, no browser-first constraint. Resource routing makes the operation's identity a URL, which is the thing that changes when a field does.
- **JSON-RPC 2.0 as the wire standard** — rejected as a standard, kept as a shape: the envelope needs `apiVersion`, an `accepted` status, and receipts, none of which JSON-RPC has a slot for. Extending a named standard is worse than a small honest envelope.
- **Newline-delimited JSON as the whole protocol, no HTTP** — rejected: re-earns framing, status, content type, cancellation, and timeouts, and gives up `curl --unix-socket` usability, which is most of what keeps a hand-written contract honest.
- **gRPC / protobuf** — rejected: a codegen toolchain and a second schema technology for one consumer and one Owner; `.factory/` artifacts already validate against JSON Schema. Streaming is the only real gain and NDJSON frames cover it.
- **One mixed feed for state and telemetry** — rejected: either telemetry looks authoritative or durable state inherits telemetry's loss. The split mirrors the three stores' three jobs and keeps completeness honest.
- **OpenAPI as the contract document** — rejected: it is HTTP-resource-shaped, so it would describe something we do not serve.
- **Codegen-first (schema → generated server stubs)** — rejected for v1: hand-written handlers with a schema-conformance test keep the contract honest with less machinery. The schema stays the source of truth either way, at `internal/api/schema/`.
- **Cursors omitted: subscriptions always start live** — rejected: "snapshots + subscriptions" (ADR-0005) is only true with a cursor; without one, restart recovery is a re-query race and a future UI cannot render history.
- **Multi-user auth now (pairing, per-client keys, DPoP)** — rejected for v1 by ADR-0005: one Owner, one machine. Scopes are declared now so a narrower surface later is a grant change, not a redesign.
- **Host filesystem paths as operation targets** — rejected: it would make remote/worker mode a rewrite and hand every client a traversal primitive.
- **An amend-decision operation** — rejected: a decided Checkpoint is a recorded fact; changing course is a new Checkpoint the Workflow produces.
- **Specifying the Conversation and Node View contracts now** — rejected: both depend on fog (the observability schema, conversation access). The names are reserved; the shapes arrive with a follow-up spec change.

## Consequences

- ADR-0005 is amended in detail, not reversed: the "typed local JSON API" is the Client Contract specified here; receipts live in the same SQLite database as the transition log, co-committed with the intent transition and updated with the effect's; the scoped Owner session is a per-start bearer token file with declared operation scopes.
- `docs/spec/API.md` is the durable contract; `SPEC.md` gains §2.7 (summary and pointer), a v1-scope row, a definition-of-done item in §1.5, the receipt store in §2.3, a CLI-verb-to-operation mapping in §7.3, client references in §7.4–7.5, an API version pin in §8.3, a build step in §8.6, and a fog entry in §9.1.
- Fourteen operations ship in v1, and the set is additive inside the major. Ten more ids are reserved for §7.4–7.5's surfaces and answer `not_implemented`; a reserved id binds a name and a kind, never a shape.
- Every command's receipt is durable before its response, so `accepted` is a safe answer for a slow effect and a client's retry converges — the retry is also how a client reads an in-flight command's state. A command's application is exactly-once per key; its success is not guaranteed, and the receipt says which.
- Decisions carry the refs they were decided against (`expect`), generalizing the spec's head-bound merge rule to every Owner decision; a moved target is `stale_target` with the current refs, not a silent approval of something the Owner did not see.
- Queries return `asOf.logSequence`, so feed and query compose; the snapshot-plus-suffix guarantee becomes usable by a client rather than a statement about the database.
- The fake second client joins the fake `RuntimeAdapter` as a seam test, and runs from build step 2 with the transition log — before any surface depends on the contract.
- CLI and daemon ship one release train and check `apiVersion` at startup; a self-hosted upgrade's guaranteed skew is a typed refusal, not a half-working surface.
- Loopback TCP, browser token delivery, multi-user grants, remote/worker transport, and the plugin's agent-side tool channel remain fog; the contract is host-agnostic by construction so each is an extension rather than a rewrite.
