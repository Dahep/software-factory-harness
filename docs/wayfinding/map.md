# Map: Factory

## Destination

A **written spec of "Factory"**: a meta-harness that lets the owner define deterministic workflows (code-defined, language TBD) which orchestrate agent teams — implement, review, triage, monitor, log, deploy — across multiple managed projects, each with its own tracker adapter, with per-agent capability control and SSH-based machine deployment. The spec is ready to hand off for planning/building in a later effort. Scope note: it serves the owner first with a path to other users; it ships a first milestone (the issue-driven loop) and is designed-for self-hosting (Factory manages Factory) in the short term.

## Notes

- **Domain**: agent orchestration / software factory. Skills: `grilling` + `domain-modeling` for any decision conversation; `research` for research tickets; `prototype` for shape questions.
- **Tracker convention** (no git remote yet, local-markdown tracker): open tickets are files in `docs/wayfinding/`; claim by adding `Assignee: <you>`; blocking via `Blocked-by:` lines naming sibling files; resolution goes into the ticket file before moving it to `docs/wayfinding/closed/`.
- **Settled before charting** (user decisions, treat as standing inputs):
  1. Destination = spec, not code (map is planning).
  2. Audience = the owner, with a deliberate path to other users later.
  3. Workflows are **code-defined** (users write code calling agent primitives); workflow language is undecided.
  4. Underlying harness = **hybrid, OpenCode-first** (ticket 006, 2026-11-18): Factory owns the deterministic control plane; OpenCode is the first `RuntimeAdapter`, run as a Factory-managed server per instance. ADR-0002.
  5. Factory should **self-track in the short term**; when working on other projects, agents report feedback as issues back to Factory's tracker.
  6. Steering/interaction data serves **mining into skills & workflow updates + observability** (tool calls, file access, network monitoring, debugging).
  7. Deployment = SSH to the owner's machines, cloud optional.
  8. First milestone = the **issue-driven loop** (issues → triage → implement → review → merge).
  9. Tracker adapters: pluggable interface; GitHub Issues (`gh`) as first implementation; Fizzy/Linear/others follow; permissions across trackers are a concern.
  10. Language comparison must include functional/memory-managed leaning: Roc, Mojo; also Go, TypeScript, others.
  11. Capability control = **containment-first** (ticket 009, 2026-11-18): one Project Envelope per project drives devvm (clone mode, network allowlist, secret bindings, spend measurement); agents run with full permissions inside the Project VM; Factory mediates tracker transitions and owns merge; role profiles deferred post-v1. ADR-0004.
  12. Daemon vs CLI: fetch both consumer models — sketch both in the spec, decide later.
  13. Project name: "Factory" for now.
  14. Workflow code must be **typesafe, and functional where possible** (owner, 2026-10-16, via ticket 007); Starlark's untyped-Python shape is demoted from default. The workflow-language survey runs as ticket 011.
  15. **Directive (owner, 2026-11-03): "If it is not measured, it is not improved."** Encode this everywhere in Factory: every workflow run, agent action, gate, and merge should emit measurable events; improvement activities (mining into skills/workflows, harness adaptation) must be driven by metrics, not vibes; benchmarks/evaluations are a first-class Factory concept, not an afterthought. Research tickets and design decisions must state what they'd measure.
- Inspirations to study: mattpocock/skills, T3 Code, paperclip, pi.dev, [Harness²](https://arxiv.org/abs/2610.14224) (recursive agent harnessing — ticket 012), [Swamp Club](https://swamp-club.com/) (behavior-centric AI — ticket 013; owner request 2026-10-27), Claude Code Code Mode + Pi Codemode (code-as-composition — ticket 015, Swamp companion 2026-11-18).
- All research agents dispatched at charting time are working in parallel; their results land in their ticket files.

Switching cost moderate if runtime state stays behind the adapter.
- [Tracker adapter interface & permissions](closed/003-research-tracker-adapters-and-permissions.md): draft capability adapter with a GitHub/Fizzy/Linear support+permission matrix; a list of per-agent permissions (incl. merge-adjacent) the harness must enforce itself.
- [Steer capture & observability](closed/004-research-steer-capture-observability.md): append-only, transcript-linked event log; OTel spans for timing/correlation only; privacy boundaries defined; evidence-linked mining with human approval; owner-facing run timeline.
- [Software-factory landscape survey](closed/005-research-software-factory-landscape.md): comparison of MetaGPT, ChatDev, AutoGen/AG2, OpenAI/Anthropic writes, Devin, Cursor, Copilot, Jules, OpenHands, SWE-agent; recurring spaghetti-agents anti-patterns cataloged with adopt/avoid recommendations. Amended 2026-10-14 (owner request): [Tessl](https://tessl.io) — the closed-source "context-driven factory" platform whose skills→loops→factory thesis challenges the code-defined-workflow premise, plus a five-system open-source factory sweep (AI Workflow, Open SWE, Vercel Foreman, gh-aw, agent-orchestrator; detail in `docs/research/oss-agent-factories-2026-10-14.md`) — no system yet combines multi-project scope, tracker neutrality, enforced capability control, and an authoritative issue→merge loop.
- [Which language does the spec commit the harness to?](closed/007-decide-harness-language.md): **Go** for the harness core (ADR-0001 with reopen triggers); OpenCode-seam cost deferred to ticket 006; workflow-code constraint tightened to **typesafe + functional where possible**, Starlark demoted — survey runs as ticket 011.
- [Survey typed functional workflow languages for a Go Factory core](closed/011-research-typed-functional-workflow-language.md): **typed, declarative workflow graph owned and interpreted by Go, with CEL for guards**; Dhall is the best-fit authoring syntax but `dhall-golang`'s v19-vs-standard-23.1 lag is an adoption gate — version the IR independently until a conformance spike passes. Fallbacks: versioned subprocess/JSON worker (native OCaml first, then Gleam/F#), then WASM/via-wazero when ABI+startup proven, Roc only post-0.1.
- [Study Harness² (recursive agent harnessing) as a Factory design input](closed/012-research-harness2-recursive-harnessing.md): adapt the **eight-component harness taxonomy** as the capability-profile vocabulary (with an enforcement axis — OpenCode freezes context assembly; only plugins+permissions enforce); **Harness²'s PPC recursion confirms 011's engine-owns-effects** (its scheduler is itself deterministic); its **improvement-library contract (cue/lesson/evidence, gated admission) upgrades closed/004** without re-opening it — keep human approval, add cross-run persistence. 006 and 009 gain reshape criteria, not re-openings.
- [Study Swamp Club's behavior-centric design as a Factory design input](closed/013-research-swamp-club-behavior-centric.md): **copy Swamp's patterns, don't build on it** (AGPLv3 core + closed registry + mandatory swamp-club.com account even for local runs). Swamp **corroborates 011** — its engine is independently a typed declarative workflow DAG with CEL guards. Adopt: YAML+JSON-Schema authoring frontend candidate beside Dhall, default-deny grant model (reshapes 009), skills+CLI harness-neutral seam across nine harnesses (lowers 002's switching-cost stakes), vaults / versioned data with lifetimes / OTel-audit split (reshape material for 010's daemon model); avoid v1: public registry, remote-worker fleet (SSH deploy stands). `@swamp/software-factory` = the issue-driven loop as data with **zero control over the driving agent** — considered for Factory's core, rejected.
- [Study Zed's DeltaDB (operation-level version control) as a Factory design input](closed/014-research-deltadb-operation-level-vcs.md): **pattern to copy, not substrate to adopt** (ships only inside Delta — no SDK/source, hosted, no permission system). DeltaId-stable operations + CRDT causal DAG **validate** closed/004's log and 002's transition-first runner (simplification candidate: append-only transitions + materialized frontier); directive #15 finds its native *pattern* here, not substrate. No-PR evidence from Zed's own repo feeds **008's merge-gate decision** — review = subthread with isolated worktree + change-guide skill; sharp rule: a skill proposes, a harness-enforced rule disposes — the gate can never live in an LLM-interpreted file.
- [Study Claude Code Code Mode and Pi Codemode as Factory design inputs](closed/015-research-code-mode-claude-pi.md): **code mode is real but is not the workflow layer** — adopt the pattern (measure the win; only Cloudflare's 99.9% tool-definition figure is a published method; Anthropic's honest full-task number is 37%). Adopt **Pi's sandbox reference design** as the spec (QuickJS-WASM, tools-only reach, exposure modes, 3k-token inline budget, transcript state, per-script budgets); **avoid** Claude's auto-mode classifier (documented blind spot — Factory checks at the tool layer) and scripts-as-workflow (LLM-authored, untyped, never replayed vs 011's graph; the only bridge is **promotion** through typing+review). Reshapes 006 (optional sandboxed composition surface), 008 (composition inside steps, gates stay graph-owned), 009 (sandbox as permission boundary); closed/011 strengthened, no re-open.
- [Decide — build on OpenCode + plugins or implement our own harness?](closed/006-decide-harness-substrate.md): **hybrid, OpenCode-first** (ADR-0002) — Factory's Go control plane owns state/gates/audit/isolation; OpenCode is the v1 `RuntimeAdapter`, Factory-managed server per instance, T3 Code–shaped contract (Task in/Outcome out + normalized telemetry + declared capabilities + driver/instance split); minimal Factory plugin; Factory-managed per-project runtime config; composition surface reserved, not built; append-only transitions + projections + snapshots. Fake runtime proves the seam; no second real adapter in v1.
- [Decide — shape of the first milestone, the issue-driven loop](closed/008-shape-the-issue-driven-loop.md): **the v1 Loop** (ADR-0003) — new issues auto-triage; typed TriageDecision owner-approved; implement → gates → review (1 implementer + 2 reviewers, wave is Workflow data); always a PR; owner-approved **squash merge via `gh`**, Factory holds the only merge capability; gates carry workflow-defined failure policies (2 fix rounds then Blocked); concurrency workflow-configurable (default 1); adoption via **init PR adding an in-repo Workflow Artifact**; Factory is subproject one (initial build manual, then self-driven); measures stage timings, gate/review/retry/cost, tool errors, agent-confusion proxies. Glossary captured in `CONTEXT.md`.
- [Study devvm as Factory's sandboxing and per-thread secret layer](closed/017-research-devvm-sandboxing.md): **adapt devvm** (MIT, Lima/QEMU, pin ≥0.1.1) as the isolation + secret layer under the RuntimeAdapter. **Owner decision: one Project VM per Managed Project** — the sandbox/secret/network boundary is the project; per-Run VM is only an escalation, so the 17-VM cap isn't a v1 limit; runtime server lives in the project VM, control plane on the host via `devvm host` + SSH. Secrets: host-side values, per-VM-random **placeholders**, host+method+path-scoped injection; custom per-project secrets make 009's profiles enforceable (HTTPS/gh/git-HTTPS/model APIs, not git-over-SSH); fail-closed. Egress = allowlist tiers with structured `network log --json` (ingest into the 004 envelope before `devvm rm` deletes it). Linux: no `.git` protection → use `--clone`.
- [Decide — capability control model](closed/009-decide-capability-control-model.md): **containment-first** (ADR-0004) — no profile system in v1. One **Project Envelope** per project in the Workflow Artifact drives devvm: `--clone` (real repo never mounted), allowlist tier with developer preset, secret bindings (GitHub + model providers), spend measured not capped. Agents unrestricted inside the VM; **tracker transitions via Factory** (comments direct); agent pushes branch, **Factory owns PR + merge**; PR-format validators reserved post-v1; nothing else always-asks; **Egress Requests** surface to the Owner. Profiles return post-v1 as narrower envelopes on the same path.
- [Decide — resident daemon vs CLI/cron invocation model](closed/010-decide-daemon-or-cli.md): **resident daemon + CLI client** (ADR-0005) — systemd user unit on the owner's machine; one SQLite (WAL) DB, daemon-only writer (append-only log + projections + snapshots); polling intake (webhooks post-v1); typed local JSON API over a Unix socket with idempotent commands + receipts; reconcile-and-resume on restart (lost VM → Blocked with evidence); Project VMs start on demand and stop on idle (~30 min). Deploy fog graduated to ticket 018.

## Not yet specified

- **Permission model for agents**: how profiles + always-ask interact with tracker permissions; exact autonomy levels. Substrate is settled (closed/006: enforcement in adapter + minimal plugin). devvm (closed/017) supplies the sandbox ceiling — VM lifetime, network tier, secret bindings; exact profiles belong to ticket 009.
- **Observability schema**: what is recorded about every steer/tool call/file/network action, and how mining consumes it. 004 decided the log shape; the schema detail remains fog, now under the measure-everything directive (#15). Network events get a concrete source: devvm's structured `network log --json` (closed/017), ingested into the 004 envelope.
- **Path-to-other-users surface**: packaging, onboarding, config UI. Later.

## Out of scope

- Building the harness or an MVP inside this map — execution follows the spec in a later effort.
- Product/UI design for other users — audience path is noted, but design starts after the owner's needs are fully specified.
- Specific cloud-provider deploy integrations — v1 is SSH to the owner's machines, cloud is optional and unspecified.
